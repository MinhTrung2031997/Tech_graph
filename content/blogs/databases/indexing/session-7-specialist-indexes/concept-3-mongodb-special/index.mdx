<Tldr>
MongoDB has index types that do more than speed up lookups. A **TTL index** makes a background thread delete documents once a date field is older than `expireAfterSeconds` (in the lab, an hour-old document vanished within ≈ 70 s; one whose field was not a date stayed forever). A **wildcard index** `attrs.$**` indexes every field under `attrs` (500 keys for `attrs.brand = 'brand7'`). A **text index** finds words (a two-word phrase search examined 45,000 keys and 40,000 documents to return 5,000). A **hashed index** serves equality (20 keys) but not ranges (COLLSCAN). PostgreSQL and MySQL reach the same goals with partitions and scheduled deletes, GIN / FULLTEXT, and hash partitioning.
</Tldr>

## The four types at a glance

| Type | Created with | Does | Lab |
|---|---|---|---|
| TTL | `{ created_at: 1 }, { expireAfterSeconds: N }` | Deletes documents whose date is older than N seconds | Expired doc removed within ≈ 70 s; non-date field kept |
| Wildcard | `{ "attrs.$**": 1 }` | Indexes every path and value under a field | 2.4 MB; 500 keys for one brand |
| Text | `{ description: "text" }` | Stemmed words, `$text` search, relevance score | 6.1 MB; 45,000 keys / 40,000 docs / 5,000 returned for a phrase |
| Hashed | `{ user_id: "hashed" }` | B-tree on hash(value); spreads shard keys | Equality 20 keys; range → COLLSCAN |

| Term | Meaning |
|---|---|
| TTL monitor | Background thread that runs about every 60 s and deletes expired documents through the index |
| `$text` | Query operator for text indexes; one text index per collection |
| **✓ Index serves it / ✗ Not served** | Per index type below |

## The same goals in PostgreSQL and MySQL

| Goal | MongoDB | PostgreSQL | MySQL |
|---|---|---|---|
| Expire old data | TTL index | Time partitions + `DROP` (or a scheduled `DELETE` with a B-tree on the date) | Time partitions + `DROP PARTITION`, or an event / cron `DELETE` |
| Index unknown fields | Wildcard | GIN on jsonb (Concept 1) | Functional or multi-valued indexes per path |
| Search words | Text index | GIN on tsvector | FULLTEXT |
| Spread keys across nodes | Hashed shard key | Hash partitioning (`PARTITION BY HASH`); Citus for distribution | `PARTITION BY HASH` / KEY |

<Pitfall>
A TTL index deletes documents one by one, as ordinary deletes, and the monitor runs only about once a minute. Expiring millions of documents a day creates heavy delete load, replication traffic and cache churn. For high-volume expiry, prefer time-bucketed collections you drop whole, or time-series collections with `expireAfterSeconds`, which drop whole buckets.
</Pitfall>

## Real-world scenario: session storage

User sessions are stored with `lastSeen`, and should disappear after 30 days of inactivity.

| Engine | Approach |
|---|---|
| MongoDB | TTL index on `lastSeen` with `expireAfterSeconds: 2592000`; update `lastSeen` on activity to postpone expiry |
| PostgreSQL | B-tree on `last_seen`; a nightly `DELETE … WHERE last_seen < now() - interval '30 days'` in batches; or a cache like Redis with native TTL |
| MySQL | Same as PostgreSQL, scheduled by the event scheduler |

## Key takeaways

1. TTL indexes let MongoDB delete expired documents in the background (about every 60 s), only for date values.
2. Wildcard indexes index every path under a field; each query uses one path.
3. Text indexes find stemmed words; multi-term queries scan each term and verify on the documents.
4. Hashed indexes serve equality and even shard distribution, never ranges.
5. PostgreSQL and MySQL reach the same goals with partition drops, GIN / FULLTEXT and hash partitioning.
