<Tldr>
A document can hold an array, and MongoDB indexes it by creating **one index entry per element**: an index on `tags` over 100,000 products with 3–5 tags each holds **400,000 entries**. `find({ tags: 'sale' })` then becomes an ordinary B-tree lookup (40,000 keys, 40,000 documents). The index is flagged **multikey**, which brings restrictions: it can never cover a query on the array field, a compound index may contain **at most one** array field (`CannotIndexParallelArrays`), and `$all: ['sale', 'eco']` seeks on one value and checks the rest per document (40,000 keys for 3,333 results). PostgreSQL indexes arrays with GIN (Session 7) and MySQL with multi-valued indexes on JSON arrays.
</Tldr>

## One document, many entries

| Document | Entries in `{ tags: 1 }` |
|---|---|
| `{ _id: 1, tags: ['red', 'sale', 'eco'] }` | `'eco' → 1`, `'red' → 1`, `'sale' → 1` |
| `{ _id: 2, tags: ['sale', 'kids'] }` | `'kids' → 2`, `'sale' → 2` |

| Lab collection `products` (100,000 docs) | Value |
|---|---|
| Tag elements in total | 400,000 |
| `{ tags: 1 }` index | 2.0 MB (10 distinct values, prefix-compressed) |
| `{ price: 1 }` index (scalar) | 0.8 MB |
| `{ tags: 1, price: 1 }` | 5.6 MB: one entry per tag, each with the document's price |

| Term | Meaning |
|---|---|
| Multikey index | An index where some document contributed more than one key; `isMultiKey: true` in explain |
| Parallel arrays | Two array fields in one compound index: would need every combination of elements, so it is refused |
| Covered query | Not possible on an array field: an entry holds one element, not the whole array |
| **✓ One array field / ✗ Two array fields** | Compound multikey index allowed or refused |

### Compound multikey bounds

`{ tags: 1, price: 1 }` works (only `tags` is an array): `find({ tags: 'sale', price: { $lt: 50 } })` had bounds `tags: ['sale','sale'], price: [-inf, 50)` and examined exactly **4,000** keys for 4,000 results. Bounds on two conditions over the **same** array field are more subtle: `tags: { $gt: 'a', $lt: 'c' }` may match a document whose elements satisfy each condition separately, so MongoDB cannot always combine the bounds; `$elemMatch` asks for one element satisfying all conditions.

## Arrays in PostgreSQL and MySQL

| | MongoDB | PostgreSQL | MySQL 8.0.17+ |
|---|---|---|---|
| Array storage | Native arrays in documents | `text[]` arrays or `jsonb` | JSON arrays |
| Index | Multikey B-tree (one entry per element) | GIN: one entry per element, posting lists of rows (Session 7) | Multi-valued index: `INDEX ((CAST(tags->'$' AS CHAR(10) ARRAY)))` |
| Query | `{ tags: 'sale' }`, `$all`, `$elemMatch` | `tags @> ARRAY['sale','eco']` (GIN intersects both values) | `'sale' MEMBER OF (tags)`, `JSON_CONTAINS`, `JSON_OVERLAPS` |
| Normalised alternative | — | A `product_tags (product_id, tag)` table with a B-tree on `(tag, product_id)` | Same |

<Pitfall>
Unbounded arrays make unbounded index entries. A document with a 10,000-element `followers` array creates 10,000 entries in every multikey index on it, and every update that adds one element rewrites the document and adds an entry. Keep indexed arrays small and bounded; model large one-to-many relations as separate documents.
</Pitfall>

## Real-world scenario: product filters

A shop filters products by several tags at once ("sale" AND "eco" AND "kids"). With a multikey index on `tags`, each filter seeks on the rarest tag MongoDB picks and fetches every product with it to check the others.

| Option | Work for 3 tags |
|---|---|
| Multikey `{ tags: 1 }` + `$all` | All products with one tag, checked per document |
| Multikey `{ tags: 1, price: 1 }` + price range | Seek on tag + price range, then check other tags |
| PostgreSQL GIN on `tags` | Intersect three posting lists, then fetch only matches |
| Search engine (Atlas Search, Elasticsearch) | Built for many-facet intersection |

## Key takeaways

1. A multikey index has one entry per array element: 400,000 entries for 100,000 products with 3–5 tags.
2. Equality on an element is an ordinary seek; `$all` seeks on one element and checks the others per document.
3. Multikey indexes cannot cover queries on the array field.
4. A compound index may contain at most one array field per document (`CannotIndexParallelArrays`).
5. PostgreSQL indexes arrays with GIN (posting lists that can be intersected); MySQL with multi-valued indexes on JSON arrays.
6. Keep indexed arrays small: every element is an entry and every change an index write.
