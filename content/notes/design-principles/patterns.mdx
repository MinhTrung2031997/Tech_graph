## Design Patterns

Reusable solutions for common problems in OOP software design.

### Creational Patterns

How to create objects.

- **Singleton** – Only one instance of a class.
- **Factory Method** – Create object without exposing logic.
- **Abstract Factory** – Create families of objects.
- **Builder** – Build complex objects step-by-step.
- **Prototype** – Clone existing objects.

### Structural Patterns

How to build class structure.

- **Adapter** – Convert one interface to another.
- **Decorator** – Add features to an object dynamically.
- **Facade** – Provide a simple interface for a complex system.
- **Proxy** – Control access to an object.

### Behavioral Patterns

How objects communicate.

- **Observer** – Notify subscribers automatically.
- **Strategy** – Swap algorithms at runtime.
- **Command** – Encapsulate operations as objects.
- **Mediator** – Central controller for communication.
- **State** – Change behavior based on object’s state.

## Architectural Patterns

High-level application structures.

- **MVC** – Model / View / Controller
- **MVVM** – Model / View / ViewModel
- **Clean Architecture** – Independent layers
- **Microservices** – Many small independent services
- **Event-Driven Architecture** – Publish / subscribe
- **CQRS** – Separate read and write models
- **Serverless** – Functions-as-a-Service

## System Design Patterns

Patterns for distributed systems.

- **Load Balancing**
- **Caching**
- **Database Sharding**
- **Rate Limiting**
- **Circuit Breaker**
- **API Gateway**
- **Message Queue**
- **Saga Pattern** (microservices transactions)

## Coding Patterns

- DRY – Don't Repeat Yourself
- KISS – Keep It Simple
- SOLID Principles
- Repository Pattern
- Dependency Injection
